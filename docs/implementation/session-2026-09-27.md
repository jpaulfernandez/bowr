## Open fault: sign-in on staging

The owner requested a link twice. Both times the link returned to the app and the owner was left on the sign-in screen with no error.

- The email is delivered, but Gmail files it as spam.
- The app sends a PKCE challenge and the correct callback URL.
- The server creates a session for each attempt.
- The app's first API call, `get_bootstrap`, has never reached the database.

So the session is lost or discarded in the browser before or during the first API call. The cause is not found. An early theory, that hosted email confirmation was responsible, was disproved by the second attempt.

Next step: observe one real sign-in in a browser with the network and console visible, or read the `api` Edge Function logs for `/v1/bootstrap`. Wait for the email rate limit to clear first. Details are in [P0.02.md](evidence/P0.02.md).
