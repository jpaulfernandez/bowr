**Slice ID and outcome:** P0.05. ### What each case proves

- **A1:** The first diagnostic settles in normal mode (settled ≤ reserved), and month-to-date rises by exactly the settled amount. After the owner sets lighter and stop to $0 (a revisioned PATCH through a confirmation dialog), the next diagnostic is `refused` with `budget_stop` while the fake provider records **0** `countTokens` and **0** `generateContent` calls. The gateway reserves before counting tokens so that a refusal makes no provider contact at all. The refusal is recorded in the ledger, and members see `paused`. Upload validation still reaches ready at a zero allowance with no model call. Members get 404 from diagnostic and budget endpoints. A $10.000001 ceiling is refused (422), a direct table write violates `budget_threshold_order`, and a stale revision gets `REVISION_CONFLICT`.
- **A2:** With $9.40 settled, 20 parallel $0.01 lighter reservations admit exactly 10; settled plus reserved is at most $9.50. With $7.95 settled, 20 parallel requests admit exactly 5 in normal mode, reaching exactly $8.00, and reprice the other 15 to the $0.005 lighter envelope. pgTAP confirms a request crossing $8 is repriced and a request past $9.50 is refused.
- **A3:** A provider timeout marks the attempt `unknown`. Its reservation stays in both reserved and unknown totals. Reconciliation does not free it, and repeating the same request identity returns `uncertain` without a second `generateContent`. `400` and `429` are released exactly once (period totals return to their prior values), and `500` is treated as possibly billed. A duplicate settlement is a no-op.
- **A4:** A tariff change between reservation and dispatch releases the reservation (`tariff_changed`). A call within the dispatch window of 00:00 UTC on the 1st is refused (`rollover_window`). An unknown September attempt becomes an October hold that counts against October and is released when the attempt settles; the charge is recorded once, in September. A missing price version fails closed (`AI_CONFIGURATION_INVALID`). A charge above its reservation settles the real amount, pauses AI (`over_reservation`), writes an audit alert, and refuses the next call with no provider contact until the owner deliberately resumes. Invalid model output is still costed and never returned as trusted output. Deno tests pin the price math: switching at the effective date, fail-closed on overlapping prices, reservation above any admitted charge, and thinking tokens billed as output.
- **A5 (local part):** The admin page shows the reset as "Oct 1, 2026, 8:00 AM (Asia/Manila)" and "Sep 30, 2026, 8:00 PM (America/New_York)", taken from the server's UTC period end.

## Database, object and ledger evidence

- The ledger is `private.ai_usage` (one row per attempt identity) plus period totals and holds. The admin view shows settled, reserved, unknown, held and remaining amounts, spend by task, and spend by member (display name and amounts only).
- Found during this slice: Supabase enables `pg_safeupdate` for PostgREST sessions, which refused singleton `UPDATE` statements without `WHERE`. That silently broke threshold changes and the over-reservation pause (which rolled back the settlement). pgTAP runs as `postgres` and missed it; the API-level integration tests caught it. Both statements now use `where id`, and every migration was scanned for the same pattern.

## Accessibility, recovery and zero-AI checks

The admin page passes axe with the AI spend section. Threshold changes require a confirmation that shows the new values and the amount already committed this month. At zero allowance, manual and non-AI processing continue (the upload-validation case above).

## Deployment flag and rollback

AI is disabled unless `AI_ENABLED=true` and a key are configured. Staging must set it only after T5 verification; the status then reads `unavailable` for members. Rollback: set `AI_ENABLED=false` or the stop to $0. The ledger is retained.
