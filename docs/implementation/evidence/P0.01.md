### What each case proves

- **A1:** Anonymous identities have no grant on `public.profiles`. Pending, suspended and deleting identities read zero profiles, including their own. A reads only A; direct writes are denied (`42501`). `update_profile` rejects `role`, `id` and `state` with `VALIDATION_FAILED`. The allowlist test fails if any new `public` table or function is exposed to `anon` or `authenticated` without an explicit grant. Owner bootstrap succeeds once, is audited, returns `OWNER_ALREADY_EXISTS` afterwards, and is not executable by `anon`, `authenticated` or `service_role`. Mutation check: temporarily replacing the RLS policy with `using (true)` and granting anon select made 8 assertions fail; restoring it made them pass.
- **A1 idempotency and revisions:** The same key and body returns the stored result without applying twice. A changed body under the same key returns `IDEMPOTENCY_CONFLICT`, and a stale revision returns `REVISION_CONFLICT`.
- **A2:** An anonymous reload of `/settings` redirects to `/auth?returnTo=%2Fsettings`, and after the email link the user lands on `/settings`. Forged values (`https://evil.example/settings`, `//evil.example`, `/%2F%2Fevil.example`, `/\evil.example`, `/invite`) land on `/wardrobe`. A member opening `/` reaches Bower; a pending identity reaches `/invite`. Expired, reused and other-browser links show a recovery route.
- **A3:** With A's profile read held in flight, signing out cancels private queries and clears the cache. The released response renders nothing, `bowr-auth` session keys are removed, and A's unsaved draft is gone. B then signs in on the same tab and sees only B's settings. A second tab in the same browser is signed out, and a new tab after the first closes must sign in again (tab-scoped `sessionStorage`).
- **A3 limitation:** On the web, completing sign-in always loads a new document through `/auth/callback`, so a same-document A→B switch cannot occur. The test covers the reachable paths: in-flight A work across sign-out, then B on the same tab. Responses whose captured user ID no longer matches the current session are also discarded by `StaleAccountError` in `apps/app/src/lib/api.ts`.
- **A4:** axe reports no WCAG 2.0/2.1/2.2 A/AA violations on `/`, `/auth`, `/privacy`, `/invite` (pending), `/wardrobe`, `/more` and `/settings`. There is no horizontal overflow at 320 px, or at 640 px with 200% zoom. The skip link comes first in tab order, settings can be edited and saved with the keyboard alone, and focused controls have a visible outline. No CSP violations are logged. Deep links return the app shell with CSP (`default-src 'self'`, `frame-ancestors 'none'`, no `unsafe-eval`), `Referrer-Policy: no-referrer`, `nosniff` and `DENY`. Missing build assets return 404, the manifest is served, and no service worker is registered. `check-web-bundle.mjs` finds no source maps, secret keys, secret variable names or non-anon JWTs; a planted `sb_secret_…` value made it fail.

## Remaining failures, withheld gates and follow-up

- **Withheld (device/human):** real phone browser, screen reader (VoiceOver/TalkBack), and OS text-size checks on a physical device. The automated phone check uses Pixel 7 emulation only.
- **Withheld (deployment):** deep-link reloads, both auth callbacks and headers on the deployed Vercel host (P0.07-A4). Google OAuth is not configured locally, and its button is hidden unless `EXPO_PUBLIC_AUTH_GOOGLE_ENABLED=true` (P0.02-T3).
- **Local limitation:** the Supabase CLI's Kong gateway overwrites Edge Function CORS headers with `*`. The function itself returns exact-origin CORS from `APP_ORIGINS`; verify on staging. Bearer-token authentication means wildcard CORS does not grant cookie-based cross-site access.
- **Sandbox note:** in this session's container, the local Edge runtime could not reach the npm registry through the TLS-intercepting proxy, so a local-only registry relay was used. Nothing in the repository depends on it.
- **Native:** the native auth-storage adapter is memory-only until the phase-8 secure adapter.
