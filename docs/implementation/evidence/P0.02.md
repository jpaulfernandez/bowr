### What each case proves

- **A1:** Five accounts redeem one code in parallel over HTTP. Exactly one gets 200 and four get 422; the database shows `uses = 1` and one active membership. Retrying the winner returns the same `joined_at` without another use. A deterministic interleaving (the second redemption is observed blocked on the invite row lock while the first transaction is open) ends with the second seeing `unavailable`. Exhausted, revoked, expired and invalid codes return an identical error body that never contains the private note.
- **A2:** The first five attempts are evaluated (422). The sixth returns `429 RATE_LIMITED` with `Retry-After` between 3000 and 3600 seconds, and a valid code is still refused inside the window. Twelve parallel attempts from one account produce exactly five evaluations and seven throttles. The per-IP throttle (30/hour) holds across seven accounts and ignores a client-supplied `X-Forwarded-For`.
- **A2 cleanup races:** While a redemption holds the membership lock, cleanup skips that account; after commit it is active and never claimed. While cleanup holds its claim, a waiting redemption fails with `MEMBERSHIP_INACTIVE` and the invite stays unused. The maintenance endpoint deletes expired pending accounts and keeps fresh pending accounts and members. A claimed account whose Auth deletion did not complete is returned again after the five-minute retry delay. `pg_cron` → Vault → `pg_net` → `maintenance` was also exercised manually (HTTP 200, `claimed 1, deleted 1, failed 0`).
- **A4:** Members and pending identities get 404 from every admin endpoint, and anonymous callers get 401. Clients cannot execute `svc_*` functions, and even the service role cannot select `private.invite_codes` directly. Revoking an invite does not suspend the member it admitted. A member opening `/admin` is redirected and sees no Admin entry. Onboarding completes with a single "Go to my Bower" action, with no measurements, photos or permission prompts.
- **Idempotency and envelopes:** A create-invite retry with the same key returns the same invite (`200`, `code: null`); a changed body returns `409 IDEMPOTENCY_CONFLICT`; a missing `Idempotency-Key` returns 422. The plaintext code appears only in the first response.
- **Gate UI:** The paste field accepts lowercase and space-separated codes. The gate shows the 24-hour deletion time and the retry time after throttling, and supports sign-out and confirmed pending-account deletion. `/admin` and `/onboarding` pass axe and have no horizontal overflow.

## Database, object and ledger evidence

- Invite codes are stored only as `HMAC-SHA256(INVITE_HMAC_SECRET, "invite:" + normalized code)`. IPs are stored only as keyed hashes.
- Audit actions recorded: `invite_created`, `invite_revoked`, `invite_redeemed`, `pending_account_deletion_requested`, `pending_account_deleted`. No codes, notes or emails appear in audit details.
